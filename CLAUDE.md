# CLAUDE.md

Guidance for working in this repository.

## What this is

Moniger Copilot: a FastAPI service exposing `POST /ask`, which answers a
user's plain-language question about their own spending/income/tax using
their transaction history. See `docs/Moniger_Copilot_Overview.docx` (product)
and `docs/Moniger_Copilot_Engineering.docx` (architecture) for the full
writeups — this file is the short version for day-to-day editing.

## Request pipeline (in `app/main.py`, in order)

1. `classifier.classify_question` — deterministic keyword routing into
   `spending | income | tax | comparison | merchant | general`. No LLM call.
2. `gating.check_and_increment` — daily per-user quota in Redis. Raises
   `QuotaExceeded` -> HTTP 429.
3. `anonymiser.anonymise` — strips PII (emails, phone numbers, card/account
   numbers, BVN/NIN) from the raw question text into stable placeholders
   like `[ACCOUNT_1]`.
4. `context_builders.build_context` — dispatches to the builder for the
   classified category; aggregates raw transactions into a small JSON
   context block. Builders only ever read `date/amount/type/category/merchant`
   — never raw narration text — so PII can't leak in through context.
5. `cache.fingerprint` + `cache.read` — SHA-256 of
   `(user_id, category, anonymised_question, context)`. Cached values store
   the **anonymised** model output only; PII is restored on every read.
6. On a miss: `router.select_model` (Haiku vs Sonnet) ->
   `prompt_builder.build_system_prompt` / `build_messages` ->
   `router.call_model` -> `response_parser.parse`.
7. Write the anonymised parsed response to cache, then restore PII
   placeholders before returning to the client.

## Conventions to follow when editing

- **Never store real PII in Redis.** Cache writes happen *before* PII
  restoration (see step 6/7 above) — if you reorder this, you will write
  user PII into the shared cache. Restoration must always happen on the
  read path, not the write path.
- **Context builders never see raw question text.** They only take
  `transactions`. If a builder needs something from the question itself,
  that's a sign it should be a `prompt_builder` concern instead.
- **Tax figures are placeholders.** `app/prompts/tax_system_prompt.py` has
  `TODO(tax-content-owner)` markers on the band thresholds/rates — don't
  treat them as correct without checking those comments, and don't remove
  the TODO without an actual sign-off.
- **Classifier is keyword-based, not ML.** When adding a new category or
  keyword, check `tests/test_classifier.py` and re-verify
  `tests/eval/test_set.json` cases still classify as expected — a keyword
  that's too broad (e.g. bare `"shop"` matching `"shopping"`) can silently
  steal cases from another category. Quick check:
  ```bash
  python -c "
  import json
  from app.classifier import classify_question
  for c in json.load(open('tests/eval/test_set.json'))['cases']:
      actual = classify_question(c['question']).value
      print(c['id'], actual, 'OK' if actual == c['category'] else 'MISMATCH')
  "
  ```
- **`router.call_model` only sets `output_config.effort` for Sonnet** — that
  parameter errors on Haiku 4.5. Don't add it unconditionally.
- **`data/synthetic_transactions.json` figures are hand-verified.** The
  numbers in `tests/eval/test_set.json` were generated by actually running
  `app.context_builders` against that file, not by hand-calculation. If you
  change the synthetic data, re-run the context builders and update the eval
  expectations to match — don't just eyeball it.

## Commands

```bash
python -m pytest                  # unit tests (classifier, anonymiser, gating)
uvicorn app.main:app --reload     # run locally (needs Redis + ANTHROPIC_API_KEY)
```

## Things that are intentionally out of scope right now

- Multi-turn conversation memory across sessions.
- Investment advice or money-movement actions.
- Filing taxes / submitting to FIRS.
- Business/corporate tax (personal income tax only).
